# 번역기 운영

설치·사용은 [README](../README.md), 코드 구조와 API는 [구조.md](구조.md) 에 있다. 이 문서는 서버 담당자가 알아 둘 동작 방식을 적는다.

## 1. 명령

| 명령 | 하는 일 |
|---|---|
| `bash run.sh setup` | `python:3.12-slim` 이미지가 없으면 받고(받은 것은 `state/pulled_images` 에 기록), 파이썬 패키지를 `cache/pylib` 에 설치한다. 인터넷 필요. 패키지를 다시 깔아야 하는데 번역기가 떠 있으면 먼저 `stop` 하라고 하고 멈춘다 |
| `bash run.sh check` | 도커·이미지·패키지·도면 분석기 모델 서버(실행·응답·모델 이름)·디스크·포트·`UI_ALLOW` 점검 |
| `bash run.sh start` | 번역기를 (다시) 띄운다. 이미 떠 있으면 내렸다가 새 설정·새 코드로 다시 띄운다. `UI_ALLOW` 가 틀리면 떠 있던 것을 내리기 전에 멈춘다 |
| `bash run.sh stop` | 번역기 컨테이너·네트워크 삭제, 자동 재연결 감시 종료, 모델 서버에서 번역기 네트워크 연결만 뗀다 |
| `bash run.sh status` | 컨테이너 상태, 모델 서버 연결·감시 상태, 모델 이름·부하, 접속 주소 |
| `bash run.sh logs [app\|gate\|linker]` | 화면 / 중계기 / 자동 재연결 기록 |
| `bash run.sh selftest` | 동작 시험 ([7절](#7-동작-시험)) |
| `bash run.sh clean [--yes]` | stop + 파일 소유자 정리 + 남은 문서·번역본 삭제(묻는다, 기본 예) + 이미지 정리(묻는다). `--yes` 는 모든 질문에 기본값으로 답한다 |

`sudo bash run.sh ...` 로 실행해도 컨테이너는 원래 계정(`SUDO_UID`)으로 돌고, 만든 파일도 그 계정 소유로 남는다. 다만 `sudo` 로 `start` 했으면 자동 재연결 감시도 root 로 돌므로, `stop`·`start`·`clean` 도 `sudo` 로 한다(아니면 감시를 끝내지 못했다고 알리고 실패한다).

`clean` 의 `python:3.12-slim` 정리: 다른 컨테이너가 쓰고 있으면 묻지 않고 남긴다. 도면 분석기 설치 흔적(모델 서버 컨테이너, `pfdvlm.project` 라벨이 붙은 컨테이너·네트워크, `vllm/vllm-openai` 이미지)이 있거나 setup 전부터 있던 이미지면 기본으로 남긴다(`--yes` 도 남김). 도면 분석기는 `stop` 때 자기 컨테이너를 모두 지우므로 컨테이너가 없어도 같은 이미지를 다시 쓴다.

## 2. 무엇이 어디에 생기나

모든 파일은 프로젝트 폴더(`/home/user/translator`) 안에 생긴다.

| 위치 | 내용 | 생기는 때 |
|---|---|---|
| `cache/pylib/` | 화면용 파이썬 패키지 (컨테이너에 읽기 전용으로 붙음) | setup |
| `cache/pip/` | pip 내려받기 캐시. 설치가 끝나면 비운다 | setup 중에만 |
| `cache/home-app/` | 화면 컨테이너의 HOME | start |
| `cache/docker-config/` | 도커 클라이언트 설정 (`DOCKER_CONFIG`, `~/.docker` 대신) | 모든 명령 |
| `data/glossary/` | 용어집 (JSON). 화면에서 고친 내용이 바로 저장된다 | 처음부터 |
| `data/jobs/` | 올린 문서와 번역본. 보관 시간이 지나면 화면 프로그램이 지운다(켜져 있는 동안) | 문서 번역 |
| `logs/app_<시각>.log`, `logs/app_latest.log` | 화면 로그 (시작할 때마다 새 파일, 최근 20개만 둔다. 화면이 비정상 종료 뒤 다시 시작되어도 같은 파일에 이어 적는다) | start |
| `logs/linker.log` | 자동 재연결 기록 | start |
| `state/pylib.sha256` | 설치한 패키지 목록(requirements.txt)의 지문 | setup |
| `state/pulled_images` | setup 이 직접 받은 이미지 (clean 이 지울 후보) | setup |
| `state/session_secret` | 로그인 쿠키 서명 키 (본인만 읽기) | start |
| `state/ui_password` | 자동으로 만든 로그인 비밀번호 (`UI_AUTH="1"` 이고 `UI_PASSWORD` 를 비운 경우) | start |
| `state/linker.pid` | 자동 재연결 감시 프로세스 번호 | start |

도커 쪽 흔적은 컨테이너 `translator-app`, `translator-gate` 와 네트워크 `translator-int`, `translator-pub` 이다. 모두 `translator.project=<NAME_PREFIX>`(기본 `translator.project=translator`) 라벨이 붙어 있고 `stop` 이 지운다(예전 판의 `translator.project=1` 도 같은 이름이면 지운다). 이름 앞머리(`NAME_PREFIX`)와 포트를 바꾼 두 번째 복사본은 라벨이 달라 서로의 `stop`·`clean` 이 건드리지 않는다. 이 밖에 도면 분석기 모델 서버 컨테이너에 `translator-int` 연결이 하나 더해지며, 이것도 `stop` 이 뗀다(모델 서버가 멈춰 있어도 뗀다. 남겨 두면 그 컨테이너를 다시 시작할 수 없다). 시스템 서비스·예약 작업·`/etc` 설정·호스트 `/tmp` 파일은 만들지 않는다.

화면 컨테이너는 메모리(`APP_MEMORY`, 기본 8GB, 스왑 없음)·프로세스 수(512)·`/tmp` 크기(`DOC_MAX_MB` × 8, 최소 512MB, 메모리 상한 안에서 씀)에 상한을 두고, 비정상 종료하면 5번까지 저절로 다시 시작한다. 중계기는 메모리 256MB·프로세스 64개 상한이다.

## 3. 모델 서버 연결과 자동 재연결

- `start` 는 `docker network connect --alias llm translator-int pfdvlm-vllm` 으로 도면 분석기 모델 서버를 번역기 내부 네트워크에 붙인다. 화면은 `http://llm:8000/v1` 로 모델 서버를 부른다. 이미 붙어 있으면 그대로 둔다.
- 도면 분석기를 다시 시작하면 모델 서버 컨테이너가 새로 만들어져 이 연결이 사라진다. `start` 가 뒤에서 띄우는 감시 프로세스(`scripts/linker.sh`)가 `docker events` 로 그 컨테이너의 시작을 지켜보다가 다시 붙인다. 이벤트를 놓쳐도 5분마다 한 번은 직접 확인한다.
- 감시 프로세스는 `setsid nohup` 으로 떠서 SSH 접속이 끊겨도 돈다. 기록은 `logs/linker.log`, 프로세스 번호는 `state/linker.pid`. `stop` 이 프로세스 묶음째(내부의 `docker events` 포함) 끝내고, 끝났는지 확인한다.
- 번역기 내부 네트워크가 없어지면(`stop`) 감시도 끝난다. 도커 데몬이 다시 시작되는 중이라 답하지 않을 때는 끝내지 않고 기다렸다가 이어서 지켜본다.

```
2026-10-05 09:00:01 감시 시작: pfdvlm-vllm (pid 12345)
2026-10-05 11:20:43 연결함: pfdvlm-vllm → translator-int (별칭 llm)
```

- 모델 서버가 없을 때 `start` 하면 화면은 띄우고 경고만 한다. 도면 분석기가 켜지는 순간 감시 프로세스가 연결한다.
- 화면은 모델 이름을 `GET /v1/models` 로 알아낸다(`LLM_MODEL` 이 비어 있을 때). 도면 분석기가 다른 프로파일(FP8 등)로 바뀌어 이름이 달라지면 다시 알아낸다.
- 동시 요청: 번역기 전체 3개(`LLM_MAX_PARALLEL`), 그중 문서 번역 2개(`LLM_DOC_PARALLEL`). 모델 서버의 한도 8개 중 나머지는 도면 분석기 몫이다. 텍스트 번역 요청은 기다리는 문서 번역 요청보다 항상 먼저 보낸다. 화면에서 번역을 취소하면 모델 서버의 생성도 바로 멈춘다.
- `status` 의 "처리 중 · 대기"는 모델 서버 전체(도면 분석기 요청 포함) 수치다(`/metrics`).
- `stop`·`clean` 은 번역기 네트워크 쪽 연결만 뗀다. 도면 분석기의 컨테이너·네트워크(`pfdvlm-int`, `pfdvlm-pub`)는 멈추거나 바꾸지 않는다.

## 4. 로그

- 화면 로그: `logs/app_<시각>.log` (`bash run.sh logs`). 웹 접속 기록(주소·문서 이름)은 끄고 띄운다(`--no-access-log`).
- 중계기 로그: 접속 차단·연결 실패만 남는다. 도커 로그로만 보며 컨테이너와 함께 지워진다(`bash run.sh logs gate`).
- 도커 로그는 컨테이너마다 20MB × 2개로 제한한다.
- 로그에는 오류가 난 문장 일부가 섞일 수 있으므로 서버 밖으로 가져가지 않는다.

## 5. 자료 보관

- 올린 문서와 번역본은 `data/jobs/` 에 작업별로 두고(실행 계정만 읽기), `DOC_RETENTION_HOURS`(기본 24시간)가 지나면 화면 프로그램이 지운다. 화면 프로그램이 꺼져 있는 동안에는 지우지 않으며, 다시 시작할 때 지난 것을 바로 지운다. 오래 꺼 둘 때는 `clean` 으로 지운다(묻는다, 기본 예). 화면에서 지우면 바로 지워진다. 실패·취소된 작업은 올린 파일을 바로 지운다.
- `data/jobs/` 전체가 `DOC_DISK_QUOTA_MB`(기본 2048MB)를 넘게 되면 새 문서를 받지 않는다.
- 문서 목록은 서버가 전체 목록을 보여 주지 않는다. 올린 사람의 브라우저가 기억하는 작업만 보인다.
- 용어집은 `data/glossary/*.json` 이다. 백업은 화면의 내보내기(CSV) 또는 이 폴더 복사로 한다.

## 6. 업데이트

1. 번역기를 멈춘다. 떠 있는 화면이 바꾸는 중인 코드·패키지를 바로 읽기 때문이다.

```bash
bash run.sh stop
```

2. 새 판의 파일로 바꾼다. **`config.env`, `data/`, `cache/`, `logs/`, `state/` 는 덮어쓰지 않는다** (`config.env` 를 덮어쓰면 로그인·접속 허용 범위·네트워크 대역이 기본값으로 돌아간다. 새 판에 새 설정 항목이 생겼으면 그 줄만 옮겨 적는다. 적지 않으면 기본값으로 동작한다. `data/glossary/` 는 화면에서 고친 용어집이다). FTP 는 바이너리 모드로 보낸다.
3. 패키지 목록(`requirements.txt`)이 바뀌었으면 인터넷이 될 때 설치한다. 바뀌었는지는 `start` 가 알려 준다.

```bash
bash run.sh setup
```

4. 다시 띄운다. 끝에 나오는 로그인·접속 허용 범위가 예전 설정과 같은지 본다.

```bash
bash run.sh start
```

5. 동작을 확인한다.

```bash
bash run.sh selftest
```

되돌릴 때는 이전 판의 파일로 다시 바꾸고 같은 순서를 밟는다.

## 7. 동작 시험

`bash run.sh selftest` 는 화면 컨테이너 안에서 `python -m translator_app.selftest` 를 실행한다. 화면이 쓰는 HTTP API 만 불러 다음을 확인하고, 항목별 PASS/FAIL 과 걸린 시간을 표로 보여 준다. 하나라도 실패하면 종료 코드 1.

| 항목 | 내용 |
|---|---|
| 상태 확인 | `/api/status` — 모델 연결·이름·부하 |
| 번역 영→한, 한→영 | `/api/translate` — 짧은 공개 문장 |
| 스트리밍 번역 | `/api/translate/stream` — 문단 3개, 이벤트 수와 첫 글자까지 걸린 시간 |
| 문서 DOCX·XLSX·PDF·TXT | `/api/documents` — 시험이 직접 만든 작은 문서(굵은 글씨 섞인 문단 포함)를 번역해 내려받고 열리는지·바뀌었는지 확인. 끝나면 지운다 |

로그인이 켜져 있으면 컨테이너의 `UI_USER`/`UI_PASSWORD` 로 로그인한다. 문서 시험을 빼려면 `bash run.sh selftest --skip-docs`.

## 8. 개발 PC 시험

서버 없이 개발 PC(Windows + Docker Desktop)에서 전체 흐름을 시험한다.

| 시험 | 명령 |
|---|---|
| 단위 시험 | `python -m pytest -q` |
| 종단 시험 | `bash dev/e2e_docker.sh` |

종단 시험은 도면 분석기 모델 서버 대신 가짜 모델 서버(`dev/fake_vllm.py`, 컨테이너 `e2e-fake-vllm`)를 띄우고, run.sh 를 도커 CLI 컨테이너 안에서 `setup → check → start → 재연결 → status → UI_ALLOW(틀린 값·맞는 값) → selftest → stop → clean` 순서로 돌린다. 컨테이너 자원 상한도 확인한다. 끝나면 남은 컨테이너·네트워크·프로세스(감시·`docker events`·로그 옮겨 적기)·파일이 없는지, 프로젝트 폴더 밖에 생긴 파일이 없는지, 가짜 모델 서버의 원래 네트워크가 그대로인지 확인한다. 설정은 `dev/e2e.env` 를 `TRANSLATOR_CONFIG_EXTRA` 로 덧붙여 바꾼다(서버에서는 쓰지 않는다).
